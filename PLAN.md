# План разработки приложения «2-фермер» (Flutter)

## Что я понял из материалов

| Файл | Назначение |
|---|---|
| `Пример отчёта XML.xml` | Эталонный XML-файл выгрузки из ГИС «Электронная отчётность». Корневая структура: `<Root><ReportData Id="signed"><Section Name="..."><ReportValue Name="XMLTAG_..." TypeName="Double\|String\|DateTime\|Empty" HasFormula="...">value</ReportValue>…`. Секции: **Отчет** (430 показателей), **Реквизиты** (ОКПО), **Технический** (Report_Type=`2-фермер`, период и т.п.), **Титульный** (организация, ОКПО, фиск.код, исполнитель и т.п.). |
| `Сопоставление 2-фермер.xlsx` | Таблица соответствия XML-тэг → показатель. **452 строки**, колонки: `id, xmltag_name, number_razdel, name_razdel, code_str, name_pokazatel, code_graf, name_column, filename_dbf, filename_district, field_in_file, id_form, is_service, primech, dt_start, dt_end, full_name, sort_id`. Разделы: `1 — Сельскохозяйственные культуры` (5 граф, 80 строк), `2 — Защищенный грунт` (2 графы, 8 строк), `3 — Многолетние насаждения` (6 граф, 25 строк), `Справочно` (19 показателей). |
| `формы.rar` → `2-фермер-V19.xltm`, `3-фермер-V7.xltm` | Бумажные формы (Excel-шаблоны), которые приносят в районные службы статистики. |
| `Руководство пользователя v2.docx` | UI-эталон существующей программы НКО (форма 1-НКО). Используем его как образец стиля и flow, форму подменяем на **2-фермер**. |

## Архитектура приложения

**Стек:** Flutter (desktop + web build), Dart, локальная БД `sqflite` (через `sqflite_common_ffi` для desktop). Парсинг xlsx — пакет `excel`; XML — `xml`.

**Структура БД (локально, как образец под перенос в реальную БД):**

| Таблица | Поля |
|---|---|
| `users` | `id, login, password_hash, district_name` |
| `organizations` | `id, region_code, okpo, name, konh, legal_form, district_id` |
| `reports` | `id, organization_id, form_type ('2-фермер'), period_start, period_end, version, status` |
| `report_values` | `report_id, xmltag_name, value, value_type` (соответствует `<ReportValue Name=… TypeName=…>value</ReportValue>`) |
| `mapping` | загружается из xlsx при первом запуске → справочник по `xmltag_name`. |

## Экраны (как в эталоне 1-НКО)

1. **Авторизация** — выпадающий список пользователей (по районам) + пароль.
2. **Список организаций** — поиск по ОКПО/названию, кнопка «Отчёты».
3. **Список отчётов по организации** — «Создать отчёт» (диалог: период), «Редактировать отчёт».
4. **Редактор отчёта (2-фермер)**
   - Шапка: название организации + ОКПО + КОНХ + период.
   - Вкладки: **Титульный**, **Раздел 1 — Сельскохозяйственные культуры**, **Раздел 2 — Защищенный грунт**, **Раздел 3 — Многолетние насаждения**, **Справочно**.
   - Таблица: `Наименование показателя | Код | <графа 1> | <графа 2> | …` (графы из xlsx).
   - Числовое поле принимает «.» или «,». Серые ячейки — авто-суммы, но можно редактировать вручную.
   - Кнопка «Сохранить» — пишет в `report_values`, синхронно с моделью.
5. **Экспорт в XML** — формирует файл в формате эталона (`Section` Титульный / Технический / Реквизиты / Отчет), пригодный для загрузки в ГИС.
6. **Импорт XML** — обратная операция (чтобы восстановить отчёт из выгрузки).

## Что войдёт в первый PR (MVP)

- Каркас проекта Flutter (Linux/Windows/macOS/Web).
- Загрузка `Сопоставление 2-фермер.xlsx` как asset + парсер → модель `Mapping`.
- Локальная SQLite (схема выше), демо-данные (несколько пользователей-районов, несколько организаций).
- Все 5 экранов из эталона, переключение вкладок, отрисовка таблиц показателей строго по xlsx (порядок: `number_razdel → sort_id/code_str → code_graf`).
- Ввод чисел и текстов в зависимости от `TypeName`, поддержка `,`/`.`.
- Сохранение/загрузка отчёта.
- Экспорт в XML в формате эталона + импорт из XML.
- Заглушка под подключение к «вашей БД» (один интерфейс `ReportRepository`, реализация SQLite, прокидываемый отдельной реализацией под Postgres/SQL Server, когда дадите доступ к боевой БД).
